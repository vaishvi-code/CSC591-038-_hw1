\section{Mathematical Properties \& Spectrum Analysis}
%% =========================================================

\subsection*{Sparsity Before and After SVD}

Pipeline: (1)~$A$ sparse; (2)~$M$ built as dense $N{\times}N$ float64 (both code paths);
(3)~$Y=\log(\max(M,1))$ stored as sparse CSR at $T{=}1$ (entries $<$1 map to 0), dense at $T{=}10$;
(4)~$N{\times}128$ embedding is 100\% dense. All adjacency matrices are verified symmetric
(\texttt{(A!=A.T).nnz==0}); density $=$ \texttt{nnz(A)}/N$^2$.

\textbf{Why $Y$ densifies:} $M$ sums powers of the normalized transition matrix $(D^{-1}A)^r$ ($1 \le r \le T$), so every pair of nodes connected within $T$ steps receives a positive entry.
Log truncation $\log(\max(M,1))$ then retains all entries with $M \ge 1$.
At $T{=}1$, only direct neighbours ($r=1$) are nonzero, so $Y$ stays as sparse as $A$ (${\approx}0.5$--$0.8\%$).
At $T{=}10$, multi-hop reachability in small-world graphs densifies $Y$ to 50--95\%.
This explains why $N{\times}N$ storage is unavoidable, imposing $\mathcal{O}(N^2)$ memory regardless of graph sparsity.

Spectra drop steeply in the first 20--50 ranks, then flatten; $d{=}128$ lies in this flat tail.
At $T{=}1$, 128 singular values retain 63--71\% of squared spectral energy---roughly 30--37\% discarded.
The paper chooses $d{=}128$ for embedding compactness, accepting this truncation cost.
At $T{=}10$ the spectrum concentrates sharply (94--99\% retained, from logs).
Separately, Theorem~3.5 of~\cite{netmf} bounds the error of the rank-256 eigenpair
approximation of $D^{-1/2}AD^{-1/2}$ in terms of its discarded eigenvalues---a bound
that is tight when those eigenvalues are small.

\section{Closed-Form Factorization vs.\ Stochastic Training}
%% =========================================================

Theorem~2.3 of~\cite{netmf} proves that DeepWalk implicitly factorizes a closed-form PMI matrix,
providing a rigorous algebraic foundation to what was previously understood only empirically.
Embeddings are deterministic and require no SGD tuning (though NetMF still exposes hyperparameters
$T$, $d$, and $b$); for $N\lesssim10{,}000$ NetMF achieves significant classification gains,
as reported in~\cite{netmf}.

However, both code paths materialise an $N{\times}N$ float64 matrix, imposing an $\mathcal{O}(N^2)$
memory wall that is independent of graph sparsity or window size.
On a 32~GB machine a single dense copy allows up to $N\approx63{,}000$ nodes;
the naive three-copy implementation limits this to $N\approx36{,}500$.
By contrast, DeepWalk and node2vec sample random walks at $\mathcal{O}(|E|)$ cost per epoch and
maintain $\mathcal{O}(Nd)$ memory---orders of magnitude smaller for large $N$.
Stochastic methods are the only viable option for web-scale graphs ($N\sim10^6$--$10^9$).
The key contribution of NetMF is therefore theoretical: grounding stochastic methods algebraically
enables principled improvements such as choosing the factorization target or injecting side information
into $M$, without altering the random-walk procedure.
